## 以下为已停用的原200件全量人审操作记录（不要执行）

1. 打开同目录 `project_validation200_blind_review.xlsx`，先读“复核说明”，再进入“盲评成对复核”。
2. 展开同一行的依据：如果Excel不允许展开隐藏列，点击 **审阅 → 撤销工作表保护**（没有密码），选择列 **E:M**，右键 **取消隐藏**。这样可以同时看到源质量状态、原标题、完整源属性、原核心清单、正式分母、实际可靠输入和门控备注。不要修改这些列。需要时也可展开A/B完整文案列；独立三任务原文已经默认显示。
3. 对照同商品源属性与核心清单，读A/B各自的标题、卖点、短详情。输入事实不足、REVIEW/CONFLICT等源争议只写备注，不删除商品、不改正式核心分母，也不直接当作模型幻觉。
4. 只填写黄色区域。A、B各填三项：

   - `matched_attribute_count`：完整三任务文案正确表达的核心字段数，0至本行原核心总数。正常同义或单位格式可认可，同一字段一次，多值任一可靠值正确表达即可。不能用自动字面命中数代填。
   - `fluency_pass`：通顺1 / 不通顺0。允许标题短语及三条中性卖点；事实错误和通顺性分开判断。
   - `factual_error_count`：独立事实错误点数，非“有错就填1”。同一错误跨任务重复只计一次；无依据评价/效果/场景、数值范围或事实失真、身份品类错误计入。正常支持的转述、低风险直接品类语义不计错误。

5. 四个成对比较都选 `A更好 / B更好 / 持平`：标题表达质量、卖点结构、短详情自然度、整体电商专业度。没有明确差异就选持平，不鼓励为润色新增效果断言。
6. 两侧五项诊断可选填0/1：字段堆叠、机械模板化、无依据评价/效果/场景、数值或范围失真、身份/品类错误。空白不是0。事实错误>0或诊断=1时，必须在对应notes写具体原文和依据。`pair_notes`可写成对选择理由。
7. 每行填 `reviewer`（你的姓名或统一代号）与 `review_confirmed=1`。允许分批保存、以后继续；不要删除/重排商品行，不改生成文本或源信息。可以使用筛选。
8. 评审完成前不要打开 `blind_mapping.json`、veryHidden匿名映射页、带Base/LoRA名字的输出或速度报告；隐藏不等于加密。自动线索页默认隐藏，建议先独立判断，再按需查线索。
